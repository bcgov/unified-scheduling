## Implementation

- Migration-only immutable journal captures business DML, auxiliary rows, crosswalks,
  mutation receipts, retry rows and checkpoints in their actual business transaction.
  Run/outcome/failure history is retained, not erased by inverse.
- Before-images use PostgreSQL pgcrypto PGP AES256 with an external 256-bit key and
  key identifier. Private source text/SSO is encrypted, never printed in diagnostics.
  **Photo bytes are excluded from both journal and hashes.**
- Initial private-photo inserts can undo by deleting the created User. A null-to-photo
  update can restore null. Replacing a preexisting nonnull photo cannot restore old
  bytes under the approved Users-only storage rule: preview explicitly blocks
  `PreviousPrivatePhotoCannotBeRestored`. No old image is silently discarded by inverse.
  This conditional privacy/retention limitation is not an implemented old-photo backup.
- Keys are in ignored, owner-restricted `docker/migration/.env.rollback.local`.
  Restricted plaintext impact exports live on named Docker volume
  `unified-ss-migration_rollback-restricted`, under `/restricted/private` (0700),
  with files 0600. Export directories/files reject links and non-owner permissions.
  Exports include later row edits and recursively discovered later FK dependents,
  but never photo bytes.
- Preview binds SHA-256 to database, original run, key ID, immutable journal entries,
  current row hashes/versions, dependency states, later dependents and blockers.
  `ConfirmDataLoss` must equal `originalRunId:digest`. Apply requires the unchanged
  restricted export and recalculates the entire plan under source advisory/table locks.
- Dependency order is Report before Training/Scheduling, then MyTeam; later same-job
  applied runs must undo first. Training/Scheduling can independently undo with no Report.
  Parent selection ignores RolledBack runs so the preserved older completed lineage
  can resume. Linked-only business targets do not enter the created-row footprint.
- Inverse restores changed columns rather than overwriting another owner's unchanged
  columns, deletes newly created graph rows child-first, resets affected durable work/
  checkpoints/crosswalks, and verifies restored columns and deleted footprints before
  commit. Safe natural-key staging frees created User/definition identities inside the
  inverse transaction. Proven mapped receipts refresh xmin after restoration; independent
  drift is not blessed. A failed inverse rolls back first, then retains sanitized failure.
- Old runs missing original journals stay fail-closed. No synthetic before-images are
  fabricated and no whole-database restore is used.

## Defects found during real execution

1. EF model metadata includes nonphysical query mappings. Preview initially failed
   SQL42P01. Inventory now uses the actual PostgreSQL table/PK/FK catalogs, including
   composite keys and non-EF dependents.
2. Row savepoints allocate subtransaction xmin. Initial trigger incorrectly recorded
   the top transaction ID, producing conservative false later-edit detection and no
   refreshed business receipts. Immutable old journals were **not rewritten**.
   Explicit migration `20261116175334_FixSsJournalSubtransactionVersion` reads the
   actual saved row xmin. Fresh database executions verify matching versions and
   successful guarded source reapplication after inverse.
