## Durable progress implementation and limits

Migration `20261116163235_AddSsDurableProgress` adds migration-only work items,
checkpoints and run heartbeat/history/batch metadata. Applied to the two new targets.
Other older rehearsal targets need an explicit schema upgrade before current execution.

Each committed batch includes business rows, crosswalks, mutations, one outcome per
source identity, independent pending-retry records, progress and cumulative counts.
Boundaries are between indivisible units; a whole merge group can exceed BatchSize.
Fencing and source/job stop controls are rechecked under the run lock each batch.
Stale recovery uses heartbeat, falling back to start time.

Snapshots are **still fully rescanned** for group membership, duplicate identity
checks and dependencies. Crosswalks make restart replay idempotent; durable typed
timestamp/ID checkpoints record committed progress, but do not yet optimize source
fetching by skipping older pages. Pending rows therefore retry independently of an
advanced cursor. This is not a claim of optimized incremental source loading.
Equal-timestamp checkpoint IDs now compare as PostgreSQL UUID/bigint, not text.
Earlier history has its own `backfill:yyyy-MM-dd` stream and matching parent lineage.

## Guarded updates and actual-service findings

- Canonical SHA-256 includes mapped text/SSO without retaining/emitting those values.
  Photo bytes are never hashed; source photo/change stamps and target row versions
  fence the private copy to Users.
- User updates preserve Training-owned profile. Training profile composition verifies
  unchanged MyTeam mapped fields, refreshes the concurrency receipt, and emits no signal.
- Full sorted single-root group updates support changed members and adding a touching
  shift member. All member hashes/crosswalks update atomically.
- Duty single-slot graph updates rebuild owned shift/user links under the original
  full mapped-graph hash and root/event row-version guard. Qualified initial series
  attachment refreshes duty/slot proofs instead of making its own members look edited.
- Actual training report, working hours, scheduling calendar and publish preview ran
  with LoanOut enabled. Probe's added historical hour produced actual overtime
  60 minutes; no production 84-day expectation was substituted.
- The target availability service suppresses **1,320 user-minutes outside each two-hour
  away interval** in this fixture. Two historical intervals and one future interval
  measured separately. Future interval 900052 remains NeedsAction; historical intervals
  remain explicit differences. This is NOT an executed SS availability-service comparison.
- Run `docker/migration/verify-recovery-probe.sql` read-only against the named probe
  target to check retained recovery/retry/backfill/group/composition/adverse evidence.
